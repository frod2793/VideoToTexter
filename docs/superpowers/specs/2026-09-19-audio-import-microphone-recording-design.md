# VideoTexter 음성 파일 가져오기 및 마이크 녹음 설계

**상태:** 사용자 승인 완료
**기준:** `main` (`1bc91a2`)의 기존 미커밋 변경 보존
**목표:** 기존 영상 변환 흐름을 재사용해 MP3·M4A 녹음 파일과 macOS 마이크 녹음을 안전하게 텍스트로 변환한다.

## 범위

- 기존 파일 선택에서 영상과 함께 `.mp3`, `.m4a`, `.wav` 녹음 파일을 복수 선택한다.
- macOS 기본 입력 장치와 사용자가 선택한 입력 장치를 모두 지원한다.
- 선택한 출력 경로에 `녹음_YYYYMMDD_HHMMSS.m4a` 원본을 보존한다.
- 녹음이 정상 종료되면 해당 M4A 파일을 기존 작업 대기열에 자동 등록한다.
- 영상과 녹음 파일은 동일한 FFmpeg → 16kHz mono WAV → Whisper → SRT/TXT 흐름을 사용한다.

실시간 자막, 파형 표시, 녹음 편집, 음량 조절, 노이즈 제거, 여러 마이크 동시 녹음은 제외한다. 녹음 중에는 실시간 변환하지 않는다.

## 선택한 접근

앱 번들에 이미 포함된 FFmpeg의 `avfoundation` 입력을 사용한다. 새 오디오 패키지나 Objective-C 바인딩을 추가하지 않는다.

FFmpeg는 `-list_devices true`로 입력 장치를 열거하고 `default` 별칭 또는 `-audio_device_index`로 녹음 장치를 선택할 수 있다. 현재 번들 FFmpeg에는 AAC 인코더가 있으므로 M4A 원본을 추가 런타임 없이 생성할 수 있다.

검토했지만 채택하지 않은 대안은 다음과 같다.

- AVFoundation 네이티브 바인딩: 장치 제어는 정교하지만 플랫폼 전용 interop과 수명주기가 크게 늘어난다.
- 별도 캡처 패키지: 구현량은 줄 수 있지만 새 네이티브 의존성과 macOS 배포 검증 범위가 생긴다.

## 구성 요소

### 1. 음성·영상 파일 가져오기

기존 파일 선택 버튼과 다이얼로그 문구를 `영상·녹음 파일 추가`로 바꾼다. 명시 지원 형식은 기존 영상 형식과 `.mp3`, `.m4a`, `.wav`이다.

선택한 파일은 기존 `MainWindowViewModel.AddFileToQueue`를 통해 등록한다. 별도의 오디오 전용 작업 DTO나 처리 파이프라인을 만들지 않는다. FFmpeg가 미디어 길이와 오디오 스트림을 읽고, 기존 `FFmpegAudioExtractor`가 Whisper 입력 WAV를 만든다.

지원하지 않는 확장자는 대기열에 넣지 않고 사용자에게 파일명을 포함한 오류를 표시한다. 대소문자가 다른 확장자는 동일하게 처리한다.

### 2. FFmpeg 마이크 녹음 서비스

Avalonia 앱 계층에 구체 서비스 `FFmpegMicrophoneRecorder`를 둔다. 단일 구현 인터페이스는 만들지 않는다.

서비스 책임은 다음으로 제한한다.

- 번들 또는 현재 앱이 설정한 FFmpeg 실행 파일 찾기
- macOS 오디오 입력 장치 목록 조회 및 파싱
- 기본 장치 또는 선택 장치로 FFmpeg 녹음 프로세스 시작
- 한 번에 하나의 녹음만 허용
- 표준 입력의 `q` 명령으로 정상 종료하고 M4A 컨테이너 확정
- 종료 코드와 최종 파일 존재·크기를 확인한 뒤 결과 반환

선택 장치 목록에는 항상 `시스템 기본 마이크` 항목을 첫 번째로 둔다. 장치 새로고침에 실패해도 기본 마이크 항목은 유지하고 오류를 표시한다. 녹음 중에는 장치 변경과 새로고침을 막는다.

### 3. 저장과 승격

출력 경로가 비어 있거나 존재하지 않으면 녹음을 시작하지 않는다. 앱이 임의의 기본 폴더를 선택하지 않는다.

녹음은 선택한 출력 폴더의 고유 임시 파일에 기록한다. FFmpeg에 M4A 컨테이너를 명시해 임시 확장자와 무관하게 올바른 형식으로 기록한다. 정상 중지, 종료 코드 0, 비어 있지 않은 파일을 확인한 뒤에만 `녹음_YYYYMMDD_HHMMSS.m4a`로 이동한다.

같은 최종 이름이 이미 있으면 덮어쓰지 않고 초 단위 접미사를 증가시켜 고유 이름을 선택한다. 승격이 완료된 M4A만 대기열에 추가한다. 실패한 임시 파일은 최종 녹음으로 표시하지 않으며, 정리 실패 시 남은 경로를 로그에 표시한다.

### 4. UI와 상태

기존 입력 영역에 다음 요소를 추가한다.

- 입력 장치 콤보박스
- 장치 새로고침 버튼
- 녹음 시작·중지 토글 버튼
- `HH:mm:ss` 녹음 경과 시간

녹음 시작 조건은 출력 경로 선택, FFmpeg 사용 가능, 활성 녹음 없음이다. 녹음 중에는 출력 경로와 입력 장치 변경을 막고 중지 버튼만 활성화한다.

녹음 종료 후 저장된 M4A를 대기열에 추가하되 변환을 자동 시작하지 않는다. 사용자는 기존 `작업 시작/재개` 버튼으로 처리한다. 기존 큐가 실행 중이면 새 작업은 큐 순서에 따라 처리된다.

창을 닫을 때 녹음 중이면 먼저 정상 종료를 요청하고 파일 확정이 끝난 뒤 닫는다. 강제 종료처럼 정상 종료가 불가능한 경우에는 성공한 녹음으로 등록하지 않는다.

### 5. macOS 권한과 패키징

앱 번들의 `Info.plist`에 `NSMicrophoneUsageDescription`을 추가한다. 저장소에 명시적 plist가 없으므로 `build_macos.sh`가 생성하는 plist에도 같은 설명을 포함한다.

권한 거부는 녹음 실패로 처리하고, 설정에서 마이크 권한을 허용해야 한다는 메시지를 보여준다. 자동검사는 실제 마이크 권한 팝업을 열지 않는다.

## 데이터 흐름

### 기존 녹음 파일

`파일 선택 → 확장자 검증 → 작업 대기열 → FFmpeg WAV 추출 → Whisper → SRT/TXT`

### 앱 직접 녹음

`장치 조회 → 녹음 시작 → 녹음 중지 → 임시 M4A 검증·승격 → 작업 대기열 → 기존 변환 흐름`

두 경로는 대기열 등록 시점부터 같은 코드를 사용한다.

## 오류 처리

- 출력 경로 미선택: 녹음 시작 거부, 경로 선택 안내
- 마이크 권한 거부: 녹음 실패, macOS 설정 안내
- 장치 분리 또는 FFmpeg 비정상 종료: 최종 파일·작업 생성 금지
- 중지 시간 초과: 짧은 유예 후 프로세스 종료, 실패 상태와 임시 파일 경로 표시
- 최종 파일 충돌: 기존 파일 보존, 새 고유 이름 사용
- MP3·M4A에 오디오 스트림 없음: 기존 작업 실패 경로로 전달
- 녹음 중 중복 시작: 두 번째 시작 거부

## 검증

자동 검사는 다음을 증명한다.

1. 장치 목록 stderr에서 오디오 장치 인덱스와 이름을 추출한다.
2. 기본 마이크와 선택 장치에 올바른 FFmpeg 인자를 만든다.
3. 녹음 상태는 `대기 → 녹음 중 → 중지/실패` 순서를 지키며 중복 시작을 거부한다.
4. 기존 파일을 덮어쓰지 않고 고유 M4A 이름을 만든다.
5. FFmpeg로 생성한 짧은 MP3와 M4A를 실제 `FFmpegAudioExtractor`가 WAV로 변환한다.
6. 정상 확정된 녹음만 기존 대기열에 등록한다.

수동 macOS 검증은 다음과 분리한다.

- 최초 마이크 권한 허용과 거부 메시지
- 기본 마이크 5초 녹음·재생·텍스트 변환
- 선택 마이크 5초 녹음·재생·텍스트 변환
- 녹음 중 장치 분리와 창 닫기
- 실제 한국어 MP3·M4A의 SRT/TXT 결과 확인

## 완료 기준

- MP3·M4A·WAV 파일을 선택해 대기열에서 변환할 수 있다.
- 기본 마이크와 선택 마이크 녹음이 선택 경로의 M4A로 보존된다.
- 정상 녹음만 대기열에 추가되며 기존 변환 흐름을 재사용한다.
- 기존 영상 변환과 Checks 17건이 회귀하지 않는다.
- 새 자동검사, 3개 프로젝트 빌드, `git diff --check`가 통과한다.
- 실제 마이크·권한·한국어 품질을 실행하지 않은 경우 완료로 표시하지 않는다.
- 기존 미커밋 변경을 보존하고 커밋·푸시는 별도 승인 전 수행하지 않는다.
