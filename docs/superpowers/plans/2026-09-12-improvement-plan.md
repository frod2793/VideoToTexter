# Video Texter 개선 계획

작성일: 2026-09-12 · 기준 커밋: `1bc91a2` · 상태: 계획 수립, 구현 미착수

**목표:** 변환 실패를 정확히 표시하고, 사용자가 의도한 작업과 모델로 실행하며, 출력 파일과 모델을 안전하게 관리한다.

**구조:** 기존 Avalonia MVVM → JobQueueManager → VideoToTextApp → FFmpeg/Whisper/Exporter 흐름을 유지한다. 새 서비스 계층이나 병렬 처리 프레임워크를 도입하지 않고 공유 실패 처리 지점과 상태 전이를 수정한다.

**기술:** .NET 8 UI, .NET Standard 2.1 코어, Avalonia 11.2.3, Whisper.net 1.9.0, Xabe.FFmpeg 5.2.6.

**근거:** `Doc/FEATURE_SPEC.md`, `Doc/ARCHITECTURE.md`, `Doc/PROJECT_STATUS.md`와 현재 소스. 문서와 소스가 다르면 아래에 명시한 실제 동작을 기준으로 한다. 이 문서는 우선순위와 완료 조건을 정한 개선 로드맵이며, 검증되지 않은 구현 패치를 확정하지 않는다.

## 범위와 실행 원칙

- `.agents/AGENTS.md`는 현재 없다. 실행 시 다시 확인하고 사용자 전역 규칙을 적용한다.
- 각 단계를 별도 검증 가능한 변경으로 처리한다. 커밋·푸시·외부 다운로드는 현재 계획 수립 요청에 포함하지 않는다.
- 기능 확대보다 결과 신뢰성을 우선한다. 성능은 정확성 확보 뒤 같은 입력·모델·장비에서 측정한다.
- 자동 검증은 실제 production 메서드를 호출하는 최소 콘솔 검증 프로젝트 `VideoToText.Checks` 하나를 사용한다. 새 테스트 프레임워크나 런타임 추상화를 테스트만을 위해 도입하지 않는다.
- 아래 시간은 구현·집중 검증의 초기 예상이며 모델 다운로드 대기와 서명·공증은 제외한다. 총 16~24시간을 예상한다.

## 1. P0 — 실패 판정과 파일 보호 (3~5시간)

**현재 근거:** `FFmpegAudioExtractor.cs:26`은 예외를 false로 바꾸고, `VideoToTextApp.cs:72`는 추출 실패 시 루프만 종료해 결과 저장으로 넘어간다. 두 exporter는 저장 예외를 삼킨다. `VideoToTextApp.cs:68`은 원본 폴더의 고정 이름 `temp_part_N.wav`를 사용한다.

**수정 파일:** `VideoToText/Application/VideoToTextApp.cs`, `VideoToText/Infrastructure/FFmpegAudioExtractor.cs`, `SrtSubtitleExporter.cs`, `PlainTextExporter.cs`. 검증 프로젝트 생성: `VideoToText.Checks/VideoToText.Checks.csproj`, `Program.cs`.

- [ ] 기존 exporter에 디렉터리 자체를 출력 파일 경로로 전달해 저장 실패가 호출자에게 전달되지 않는 현상을 먼저 재현한다. 정상 저장과 실패 전파 검증을 같은 콘솔 실행에 넣는다.
- [ ] 추출 false는 파이프라인에서 예외로 처리한다. exporter는 예외를 상위로 전달하고 큐의 기존 Failed 처리를 재사용한다. 저장 완료 뒤에만 100%를 통지한다.
- [ ] 임시 WAV는 OS 임시 폴더의 작업별 고유 경로에 생성하고 `finally`에서 정리한다. 정리 실패가 원래 변환 예외를 덮지 않도록 분리한다.
- [ ] 출력 폴더를 생성·확인하고 기존 SRT/TXT가 있으면 해당 작업을 명시적으로 실패시켜 원본 결과를 보존한다. 출력 생성은 배타적 생성으로 충돌을 검출한다. 두 파일 중 하나만 저장되면 Failed와 남은 파일 경로를 표시한다. 두 파일 동시 원자적 저장은 이번 단계의 보장 범위가 아니다.
- [ ] **통과 조건:** 잘못된 미디어, 추출 실패, 쓰기 불가 경로가 Completed가 되지 않는다. 기존 자막과 원본 폴더의 `temp_part_1.wav` 내용이 보존된다. 정상 변환은 SRT/TXT 모두 저장되며 종료 후 작업 임시 WAV가 없다.

**수정 파일:** `JobQueueManager.cs`, `Core/IJobQueueManager.cs`, `MainWindowViewModel.cs`, `JobViewModel.cs`, `Views/MainWindow.axaml`, `VideoToText.Checks/Program.cs`.

- [ ] 초기 큐를 일시정지 상태로 두고 시작 버튼으로만 처리한다. `Func<TranscriptionJobDTO, VideoToTextApp>`으로 기존 앱 공급자에 실행 작업을 전달하고 해당 작업의 ModelName으로 모델을 선택한다. 출력 경로와 모델은 등록 시 확정하는 규칙을 UI에 표시한다.
- [ ] 일시정지는 현재 파일 완료 후 다음 파일 시작을 막는 의미로 유지하고 버튼·상태에 이를 명시한다. 일시정지 요청만으로 실행 중 표시가 사라지지 않게 한다. 즉시 중단·중간 위치 재개는 범위에서 제외한다.

- [ ] 성공·실패·취소 수를 구분한다. 실패를 처리 진행률에 포함하더라도 성공 완료로 표시하지 않는다. 로그는 문서에 적힌 100개 상한을 모든 추가 경로에 적용한다.

## 3. P1 — 자막 중복·누락 검증과 수정 (4~6시간)

**현재 근거:** `VideoToTextApp.cs:89`의 10초 중첩 결과를 그대로 합친다. `WhisperTranscriptionService.cs:42`에서 청크마다 이력이 초기화되고 `:68`에서 최근 5개와 같은 문장을 제거한다. 따라서 청크 경계 중복을 막지 못하면서 실제 반복 발화를 삭제할 수 있다.

**수정 파일:** `VideoToTextApp.cs`, `WhisperTranscriptionService.cs`, `VideoToText.Checks/Program.cs`.

- [ ] 사용자가 제공하거나 로컬에서 사용 가능한 한국어 입력으로 짧은 반복 발화와 20분 경계를 포함한 기준 샘플을 선정한다. 경계 전후 정답 문장과 시간을 사람이 확인해 기록한다. 입력이 없으면 이 단계의 음질 검증은 미증명으로 남긴다.
- [ ] 최근 5개 문자열의 전역 반복 삭제를 제거한다. 자연스러운 같은 문장 반복은 보존한다.

## 4. P1 — 모델 다운로드 완결성과 저장 위치 (2~3시간)

**현재 근거:** `MainWindowViewModel.cs:373`은 최종 모델명에 직접 쓰며 `:155`는 파일 존재만으로 다운로드됨을 판정한다. 저장 위치는 앱 실행 디렉터리 아래 Models이므로 번들 쓰기 권한과 배포 후 변경 문제를 갖는다.

**수정 파일:** `MainWindowViewModel.cs`, 필요 시 모델 경로 공유를 위한 같은 클래스의 private 메서드, `VideoToText.Checks/Program.cs`.

- [ ] 새 모델 저장 경로를 `Environment.SpecialFolder.LocalApplicationData` 아래 `VideoTexter/Models`로 통일한다. 기존 실행 디렉터리 Models은 읽기 호환 경로로 남기고 기존 파일은 삭제·이동하지 않는다.

- [ ] 기존 레거시 모델의 파일 존재는 유효성 증명이 아님을 구분한다. 실제 로딩 실패 시 해당 모델 오류를 표시하고 다른 작업의 성공으로 오인하지 않는다.

## 실행 시 공통 검증

아래 명령은 계획이며 이번 턴에 실행하지 않았다. 패키지 복원은 의존성 취득이 승인된 실행 범위에서만 수행한다.

```bash
dotnet build VideoToText.Avalonia/VideoToText.Avalonia.csproj --no-restore
dotnet run --project VideoToText.Checks/VideoToText.Checks.csproj --no-restore
git diff --check
```

체크 프로젝트는 생성 전이므로 현재 실행할 수 없다. `--no-restore`가 assets 부재로 실패하면 코드 컴파일 실패와 구분해 환경 미준비로 기록한다. 각 수정 전 관련 체크가 기대한 원인으로 실패하는지 확인하고 수정 후 통과를 확인한다. FFmpeg 실패·실제 Whisper 결과·Avalonia 표시·독립 배포는 각각 실제 실행으로 검증하며 순수 함수 검증으로 대체하지 않는다.

## 이번 범위에서 보류

병렬 Whisper 추론, 모델 스레드 수 조정, GPU 강제 활성화, Windows 배포, 예약 UI, 다국어 UI, UI 전면 개편은 보류한다. 정확성 기준을 통과한 뒤 같은 장비·모델·입력으로 3회 처리 시간과 최대 메모리를 측정하고 병목이 확인된 항목에만 별도 성능 계획을 세운다.

## 착수 순서

1단계 실패 판정과 파일 보호부터 시작한다. 단계별 통과 조건을 충족한 뒤 다음 단계로 넘어간다. 계획 수립 자체는 구현·커밋·다운로드 실행을 의미하지 않는다.
